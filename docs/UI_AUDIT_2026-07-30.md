**Date:** 2026-07-30

**Lens:** Simplicity. The product has the features; the question is whether a new

traders pick one platform over another — this audit treats "confusing" as the bug.

## TL;DR — the core diagnosis

The features are strong and several screens are genuinely well-built (Journal,
Analytics, Payouts readiness, the New-Combine pricing flow). The confusion is **not**
missing polish — it's five systemic patterns that make a capable product feel like an
expert-only instrument panel:

1. **Acronym-dense UI with the help content disconnected** from where the jargon appears.
2. **Redundant information architecture** and an unclear core noun ("account" vs "combine").
3. **A trading terminal with zero progressive disclosure** — everything is on at once.
4. **A handful of trust-eroding polish bugs.**
5. **A broken mobile experience.**

The throughline: **the UI can't explain itself, so it either stays cryptic or dumps a
wall of prose.** Simplicity-led platforms win by showing less and explaining in place.

## Severity legend

- **P0** — cheap to fix, high trust impact, visible on the first screen. Do first.
- **P1** — the actual drivers of "confusing." Where simplicity is won or lost.
- **P2** — larger / conditional (mobile, structural redesign).

## P0 — Fix first (cheap, high-trust-impact)

### P0-1 · Chart Y-axis labels collide with price labels
On **Home** and **Analytics**, the "TARGET" and "MLL" reference-line labels render
directly on top of the axis price ticks — visible as `TARGET00` over `$106,000` and
`MLL0,000` over `$100,000`. This is the first thing a user sees on the dashboard and it
reads as "broken." It is worse on mobile.
- **Where:** dashboard equity curve + `AnalyticsPage` equity curve; the reference-line
  label layer overlaps the price-axis label layer.
- **Fix:** offset the reference-line labels (left-align on the plot, or move to a legend
  row), or reserve right-gutter space so the two label sets never overlap.

### P0-2 · The chart sits on an infinite spinner with no timeout
The option chain resolves cleanly to *"SPY chain unavailable — the market-data feed is
slow to respond. Retrying automatically… [Retry now]"*. The **chart bars** query does
**not** — it stays in `isLoading` and shows "LOADING SPY CHART…" indefinitely after
hours.
- **Where:** [`AnnotatedChart.tsx:203`](../frontend/src/components/stock/AnnotatedChart.tsx)
  has a `MarketDataUnavailable` panel for the degraded case, but
  [`AnnotatedChart.tsx:211`](../frontend/src/components/stock/AnnotatedChart.tsx) keeps
  rendering `ChartSkeleton` whenever `bars.isLoading && !data`, and the bars request
  never flips to `degraded`/`error` — so the skeleton never resolves.
- **Impact:** the primary content area of the "Chart" nav item is an eternal spinner
  whenever the market is closed.
- **Fix:** give the bars query the same timeout → empty/retry treatment the chain
  already has (a "chart unavailable, retry" state after N seconds).

### P0-3 · "TRADING DAYS 13 / 2" reads as a bug
[`DashboardPage.tsx:530`](../frontend/src/pages/DashboardPage.tsx) renders
`{days_traded} / {min_trading_days}` → **"13 / 2"**: a fraction whose numerator is bigger
than its denominator, which looks like an error.
- **Fix:** phrase it as a pass state, e.g. **"Met — 13 days (2 required) ✓"** or
  **"13 days · minimum 2"**.

### P0-4 · Multiple gold CTAs compete on one screen
The dashboard shows **ACTIVATE (FREE)**, **START A TRADING COMBINE**, and **LAUNCH
TERMINAL** simultaneously, and **ACTIVATE** repeats on Accounts, Payouts, and Settings.
Everything gold = nothing is primary.
- **Fix:** one primary (filled gold) action per screen; demote the rest to
  secondary/ghost styling. Decide the single most important next action per page.

## P1 — The confusion drivers

### P1-5 · Acronym wall with orphaned help content
The terminal header alone shows 8 abbreviations: **CUSHION, MLL, BAL, RP&L, UP&L, BP,
DLL, MKT**. The abbreviations themselves are fine for a trading tool — the problem is
that the help is disconnected from where the jargon lives:

- [`ui/MetricPill.tsx`](../frontend/src/components/ui/MetricPill.tsx) — the pill used for
  BAL / MLL / DLL / CLOSED P&L on **Home and Accounts** — has **no tooltip prop at all**.
  So the most-seen numbers in the app are unexplained, even though the identical pills in
  the terminal header (`TradeDeskHeader.tsx`) carry rich `title`s.
- The searchable glossary ([`lib/glossary.ts`](../frontend/src/lib/glossary.ts)) has only
  **10 entries** and is missing ~20 live terms: ATM, EM / expected move, max pain, gamma
  flip, call/put wall, IV rank, VRP, 25d skew, P/C ratio, BP / buying power, high-water
  mark, cushion, R-multiple, theta burn, the individual greeks, and the four ML signals
  (LSTM vol, CatBoost ER, RF regime, vol edge).
- Good two-sentence definitions for most of those **already exist** in
  [`lib/tooltips.ts`](../frontend/src/lib/tooltips.ts) (18 terms) — but that file is
  imported by only **2 of ~50** jargon-bearing components (`BottomStrip.tsx`,
  `VolRegimeStrip.tsx`). The content is written; it just isn't wired up.
- The **Command Palette** (⌘K) has **no visible affordance** — no button, no hint. A new
  user will never discover it. ([`command/CommandPalette.tsx`](../frontend/src/components/command/CommandPalette.tsx))

**Fix path (mostly wiring, not authoring):** add a `hint` prop to `MetricPill` and pass
tooltips; feed `tooltips.ts` into the glossary so search covers everything; wire the
existing tooltip keys into the components that display those terms; add a discoverable
⌘K entry point (a header/rail affordance).

### P1-6 · Inconsistent core vocabulary — "Account" vs "Combine"
The same object is called four different things:
- nav item: **"Accounts"**
- header: **"1 of 5 combine slots used"**
- card heading: **"YOUR COMBINES"**
- selector: **"100K COMBINE"**

Separately, **"CLOSED P&L"** (Dashboard/Accounts) and **"RP&L"** (terminal/glossary) are
the *same number* under two names — so a glossary search for "closed p&l" returns
nothing.
- **Fix:** choose one canonical word per concept (recommend "combine" for the funded
  account object, one label for realized P&L) and use it in every surface, including the
  glossary key.

### P1-7 · Redundant screens inflate the perceived surface area
- The **Accounts** page is almost entirely a duplicate of the dashboard's "YOUR
  COMBINES" card — same BALANCE / CLOSED P&L / MLL / MLL CUSHION / DLL REMAINING.
- The combine list *also* appears in **Settings → Account** ("YOUR COMBINES" with
  "+ NEW COMBINE").
- **Journal** and **Analytics** are both "review your closed trades," with overlapping
  filter chips (ALL/PAPER/LIVE, THIS/ALL ACCOUNTS, date range, Export CSV).
- The rail exposes **8 top-level items + Admin**
  ([`LeftRail.tsx:29`](../frontend/src/components/layout/LeftRail.tsx)) for what is really
  ~4 concepts: **Trade** (terminal), **Review** (journal+analytics), **Money**
  (accounts+payouts), **Settings**.
- **Fix:** consolidate. Merge Accounts into Home (or make it a Payouts sub-view), fold
  Analytics into Journal as a tab, and cut the rail toward ~4–5 destinations. This is the
  single biggest lever on "the platform feels simpler."

### P1-8 · The terminal has no progressive disclosure
[`PositionsPage`](../frontend/src/pages/PositionsPage.tsx) composes ~**155 interactive
controls** on one screen (BottomStrip ~46, RightChain ~39, TradeTicket ~28, WorkingOrders
~23, plus toolbar/header/detail panels):
- 6 timeframe buttons + 8 indicator toggles (SMA/EMA/VWAP/BB/RSI/STOCH/MACD/ATR) always
  visible.
- A **"VOL REGIME · IVR — SKEW — VRP — TERM —"** row of pure jargon that shows only
  em-dashes when data is absent.
- Full option chain + trade ticket + tools (BUILD/SIZE/SIM) + calendar strip + key levels
  + news, all at once.
- **Impact:** this is the single densest surface and the biggest "low-level / confusing"
  complaint generator.
- **Fix:** introduce a beginner/expert split — essential controls (timeframe, buy/sell,
  chain) visible by default; indicators, vol-regime, and market-structure tools behind a
  collapsible "Advanced" toggle. Hide empty jargon rows entirely instead of showing dashes.

### P1-9 · Explanatory walls of prose
Because the UI can't explain itself inline, several screens dump paragraphs: the "Path to
Funding" footer on Home ([`DashboardPage.tsx:548`](../frontend/src/pages/DashboardPage.tsx)),
the copy-trading explainer on Accounts, and the simulated-payouts disclaimer on Payouts.
The intent is good; the mechanism is wrong.
- **Fix:** convert to tooltips / expandable "How this works" disclosures anchored to the
  specific control, so the default view stays scannable.

## P2 — Mobile is effectively broken

Walked at 375×812:
- **Terminal:** the stat bar overflows horizontally (values clipped on both edges), and
  the **entire option chain + BUY/SELL trade ticket is missing** — a user literally
  cannot place a trade — with no "desktop only" message.
- **Dashboard:** the header "1 of 5 combine slots used" is clipped off the top edge; the
  combine ID wraps mid-token as "100KTC- 11- 34039775"; the equity-curve labels still
  collide.
- **Bottom nav** ([`MobileBottomNav.tsx`](../frontend/src/components/layout/MobileBottomNav.tsx))
  crams 8 items with truncated labels: HOME, ACCOU…, PAYOU…, CHART, JOURN…, ANALY…,
  SUPPO…, SETTI….

**Decision taken:** ✅ mobile is out of scope for now — shipped a clean desktop-only gate
(`DesktopOnlyNotice`, shown below `md`) instead of a broken layout, and removed the crammed
`MobileBottomNav`. A full responsive rebuild (responsive stat bar, mobile trade sheet,
reduced nav) remains a possible future workstream if mobile becomes a priority.

## What's already good — keep and replicate these patterns

- **Payouts readiness** — numbered checklist (1. Verify identity, 2. Tax form, 3. Payout
  method) with clear "ACTION NEEDED" badges. This is the app's best onboarding pattern;
  reuse the structure elsewhere.
- **Journal calendar** — money-colored P&L days, weekly rollups, and the "Click any day
  with trades to review…" footer hint. Clean and scannable.
- **New Combine** — the "Buy your combine — the rules are the product" explainer modal +
  the clean 3-tier pricing cards. Good first-run framing.
- **Analytics** — well-composed stat cards (NET P&L / WIN RATE / PROFIT FACTOR / etc.) and
  a readable equity curve with drawdown overlay.
- **Support** — a simple, well-labeled contact form with a genuinely helpful placeholder.
- **Admin console** — appropriately dense for an internal operator audience; not a concern.

## Suggested sequencing

1. **P0 batch** (a few hours): P0-1…P0-4. Highest trust-per-line-changed; all visible on
   the first screen.
2. **P1 help + vocabulary** (P1-5, P1-6): mostly *wiring existing content*, and this is
   where "confusing" actually gets solved.
3. **P1 structural** (P1-7, P1-8): IA consolidation + terminal progressive disclosure —
   the bets that most change the simplicity story.
4. **P2 mobile**: decide scope first (gate vs. real responsive work).
